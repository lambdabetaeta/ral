A coding agent that acts through
one tool: the ral shell.

Every move it makes is a ral program, run inside a sandbox.

The agent

exarch is a small agent around one loop: show the model the conversation, run what it sends back, show it the result. What it sends back is always a ral program — there are no file-reader, editor, or shell tools to call. To read a file, edit it, or run the tests, it writes ral and runs it as one top-level turn.

Each turn runs inside a grant: which programs may run, which paths may be read or written, whether the network is on. The model never writes that grant — exarch installs it around the turn, so there is no wrapper in the source to drop and nothing to talk past. When a grant withholds files or the network, ral re-runs the command in an OS sandbox — Seatbelt on macOS, bubblewrap on Linux — enforced by the kernel, not just promised. (exarch's own process isn't sandboxed; it needs the network to reach the model.)

Because the tool is ral, what comes back is typed data, not text to re-read. Output is a value with a type, and a whole run can be captured as a tree — every command, its output, its exit, the authority in force — with a failed exit handed back as data, not thrown. The string-splicing brittleness of shell-driving agents has nowhere to arise; every session is written out in full besides, to read back later.

ral vs. a raw shell

a string-shell agent
# the model writes a string,
# and whatever it writes, runs
shell("rm -rf build")
shell("curl get.sh | sh")
exarch — ral under a grant
# the model writes the body;
# exarch wraps it in a grant
grant [exec: [git:[], cargo:[]],
       fs:   [read:  ['<cwd>'],
              write: ['<cwd>']],
       net:  false] {
  cargo test -q
}

Capability profiles

⊤ full ambient authority
✚ dangerous No limits — the authority you have at your own prompt. net inheritexec inherit
✚ reasonable Runs your toolchain; writes only the working directory and scratch. net onexec system + brew + git
✚ read-only Reads broadly; writes only to scratch. net onwrite scratch
✚ minimal System tools only — /bin and /usr/bin, no brew, no shells. net onexec /bin + /usr/bin
✚ confined Network off; reads and writes only the working directory and scratch. net offfs cwd + scratch
⊥ least authority

Providers

Any provider whose key is in your environment is found at startup — then scrubbed from the environment, so nothing exarch runs can inherit it.

anthropic openai openrouter deepseek xai qwen + custom / self-hosted

Run

$ ANTHROPIC_API_KEY=… cargo run -p exarch
✚

One verb — write ral — inside a boundary it cannot widen.
