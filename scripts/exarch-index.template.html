The exarch

In Byzantine usage, an exarch was a viceroy who acted on behalf of a distant sovereign within a bounded province. Here the sovereign is the LLM and the province is the grant.

exarch loops a chosen model against a single tool — ral. Each command the model emits is a top-level turn, evaluated under a profile's Capabilities pushed onto ral's capability stack. Typed commands, scoped authority, and an OS sandbox all fall out of one principle — without giving up first-class commands and pipes.

The exarch process itself is not sandboxed — it still needs HTTPS for the model API. But each tool call is: when caps restrict the filesystem or network, ral re-execs a child under Seatbelt on macOS or bwrap on Linux, evaluates the computation there, and returns.

       fs:   [read:  ['<cwd>'],
              write: ['<cwd>']],
       net:  false] {
  cargo test -q
}

Writs of authority

⊤ full ambient authority
✚ dangerous Lattice top. No attenuation. net inheritexec inherit
✚ reasonable Everyday agent. Broad reads, writes only ephemeral surfaces. net onexec 80+ tools
✚ read-only Inspect without mutating. Writes scratch-only. net onwrite scratch
✚ minimal System tools only. No homebrew, no xdg. net onexec /bin + /usr/bin
✚ confined Build jail. Network off, cwd + scratch only. net offfs cwd + scratch
⊥ sealed jail

The instruments

⊙

Capability-scoped

Every command runs under a profile's grant, pushed onto ral's capability stack. Authority is typed and checked before a process spawns — not a prompt-level promise.

▣

OS-sandboxed

When caps restrict the filesystem or network, ral re-execs a child under Seatbelt (macOS) or bwrap (Linux). The agent keeps HTTPS; the tool call does not.

⇄

Multi-provider

Anthropic, OpenAI, OpenRouter, DeepSeek, xAI, Qwen and more — auto-discovered from environment keys, then scrubbed at startup so no spawned child inherits them.

▤

Audited

A session.log under $EXARCH_SCRATCH captures the full transcript — unabridged stdout and stderr from every command.
